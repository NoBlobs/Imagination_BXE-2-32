# Firmware architecture

This document describes how the clean-room firmware is organised and how
control flows through it at run time. The memory layout and the boot path are in
[boot-and-memory.md](boot-and-memory.md). The host contract (`.fw` container,
shared structures, CCBs, power, trace) is in [host-interface.md](host-interface.md).
The client CCB walk and the data-master kicks are in
[scheduler-and-kicks.md](scheduler-and-kicks.md).

## Target

| Item | Value |
|---|---|
| GPU | PowerVR Rogue BXE-2-32, BVNC `36.29.52.182`, one core (`MC1`), XE family |
| SoC | SpacemiT K1 (Banana Pi BPI-F3), GPU registers at `0xCAC00000` (512 KiB), IRQ 75 |
| Firmware processor | MIPS32r2 core in the GPU wrapper ("MIPS wrapper"), **microMIPS** ISA |
| ABI | o32, soft-float, little-endian, ELF32 `EM_MIPS` |
| Caches | not used: KSEG0 is set uncached (`Config.K0 = 2`) and every TLB entry is uncached |
| Host | mainline `drm/imagination` (`powervr.ko`) + Mesa `pvr` Vulkan driver |
| Language | GNU C23 (`-std=c23`, clang) and microMIPS assembly |

## Execution model

The firmware has **no main loop and no threads**. After initialisation `fw_main`
enables interrupts and sleeps in `WAIT`. All work runs in interrupt context, one
interrupt at a time:

```
                 ┌────────────────────────────────────────────────────────┐
  HW0 timer ───▶ │ irq_dispatch(0): re-arm Compare (1 ms)                 │
  (CP0 Compare)  │   kccb_process(); sched_poll(); sched_run();           │
                 ├────────────────────────────────────────────────────────┤
  HW1 BG task ─▶ │ irq_dispatch(1): kccb_process(); sched_poll();         │
  (MTS)          │   sched_run(); MTS_TASK_END = 0                        │
                 ├────────────────────────────────────────────────────────┤
  HW2 IRQ task ▶ │ irq_dispatch(2): ev = EVENT_STATUS; EVENT_CLEAR = ev;  │
  (MTS)          │   sched_irq(ev); MTS_TASK_END = 2                      │
                 └────────────────────────────────────────────────────────┘
```

- **BG task (HW1)**: the host writes `ROGUE_CR_MTS_SCHEDULE` after it queues a KCCB
  command, and the MTS raises HW1.
- **IRQ task (HW2)**: the GPU raised an event, such as a data master finishing or an
  MMU fault.
- **Timer (HW0)**: the CP0 Count/Compare timer, every 1 ms. It is a *backstop*. It
  polls the KCCB and the completion events, so the firmware keeps working even if the
  MTS does not deliver a task (the MTS set-up is open question Q1). In practice the
  host sees the firmware answer within one tick.

All three sources share one entry, `int_common` in `vectors.S`. It saves the
caller-saved registers, EPC and Status on the wired stack. It then **clears
`EXL`/`ERL`/`IE`** before it calls C. With `EXL = 1`, a TLB miss inside the C handler
would go to the general exception vector instead of the refill vector, and EPC
would be lost ([E002](logRefs/E002-exl-in-c-handlers.md)). After the handler returns,
the original Status is restored with `EXL` set again for the `ERET`.

Interrupts are never nested. Code that runs outside the interrupt path (the boot-time
`kccb_process()` call) protects itself with `irq_save()`/`irq_restore()`.

## State

The whole firmware state is the global `struct fw_state g` (`fw.h`) plus three
module-local tables:

| Object | Where | Content |
|---|---|---|
| `g` | `main.c` | Pointers to `sysinit`, `osinit`, `sysdata`, `osdata`, `runtime_cfg`, the trace buffer, KCCB and FWCCB. Also clocks, power state, config flags and interrupt counters. |
| `ctxs[64]` | `sched.c` | Contexts seen in a KICK: firmware address, pending/dead flags, a FIFO of the kick's cleanup control blocks. |
| `dms[DM_MAX]` | `sched.c` | Per data master: busy flag, running context, cCCB offset of the running command, completion event mask, kick time, BIF slot. |
| `bif_pc[8]` | `kick.c` | Page-catalogue address bound to each `BIF_CAT_BASE` slot (slot 0 is never used for clients). |

Everything is in `.bss` at `0xC0ED0000`. It is cleared at **every** boot, including
the warm boot after a power-off. No firmware state survives a power cycle, and none
needs to: the host re-sends everything (see "Warm boot" in
[host-interface.md](host-interface.md)).

## Address helper `fwptr()`

Every firmware address the host gives (`fw_addr` fields) is a MIPS virtual address in
the 16 MiB firmware heap at `0xC0000000`. The host can set flag bits in it: bit 0
marks a sync checkpoint, and the meta-DMA/"cached" bits sit above bit 24. `fwptr()`
masks it with `0xC0FFFFFC` and returns a pointer, with null kept as null. The TLB
refill handler maps that address on demand from the host's MIPS page table.

## Module dependencies

```
 fw_main ─▶ shared_init ─▶ trace_init ─▶ mts_init ─▶ gpu_units_init ─▶ sched_init ─▶ kick_init
 irq_dispatch ─▶ kccb_process ─▶ {sched_kick, sched_cleanup, mmu_cache_op, pow_handle, ...}
              └▶ sched_poll / sched_irq ─▶ kick_events ─▶ sched_dm_done
              └▶ sched_run ─▶ ctx_process ─▶ kick_task ─▶ kick_cdm
 everything ─▶ util (TRACE, notify_host, write_barrier, cr_poll32, gpu_timer)
```
